# v3 Website Design Spec
**Date:** 2026-05-28  
**Author:** Alan Wu  
**Status:** Approved

## Overview

A complete redesign of alan-w25.github.io into a minimal, editorial personal site. The goal is a balanced writing + portfolio site inspired by nabeelqu.co, borischerny.com, and eugeneyan.com — confident simplicity where content does the work.

Primary audience: potential employers, collaborators, and readers finding Alan through his writing.

---

## Tech Stack

| Concern | Choice | Rationale |
|---|---|---|
| Framework | Astro | Static output, purpose-built for content sites, near-zero JS by default |
| Content | MDX | Markdown + optional JSX; write `.mdx` files to publish posts, code blocks and images built-in |
| Styling | Tailwind CSS v4 | Utility-first, consistent spacing scale |
| Deployment | Vercel | Existing account, Astro has first-class Vercel adapter |
| Location | `/v3/` folder | Matches v1/v2 convention; Vercel root points here |

**Publishing flow:** Create `src/content/writing/my-post.mdx` → commit → Vercel auto-deploys. No CMS, no dashboard, no API keys needed.

## Pages

### Homepage (`/`)

Single narrow column (~680px max-width), centered. No hero image. No animations.

**Sections in order:**
1. **Nav** — `Alan Wu` left-aligned, `Writing · Projects · About` right-aligned. No border, just spacing.
2. **Intro** — 3–4 sentences. Name, current role/school, what you care about. Plain prose, no bullet points.
3. **Writing** — Section label + list of 4–5 most recent posts. Each row: title (left) + date (right, muted). `→ All writing` link at bottom.
4. **Projects** — Section label + 3 project entries. Each: project name (bold) em-dash one-line description. Links to detail or external.
5. **Footer** — `Email · GitHub · LinkedIn · Resume` — small, muted, centered.

### Writing Index (`/writing`)

Full list of all posts, sorted newest first. Same row layout as homepage preview. Optionally grouped by year.

### Post (`/writing/[slug]`)

- Title (Lora serif, large)
- Date below title, muted
- Body in Lora at comfortable reading size
- No sidebar, no TOC (add TOC later if posts get long)
- `← Back to writing` link at top-left

### Projects (`/projects`)

List layout (not grid cards). Each project:
- Name + year
- 1–2 sentence description
- Tags: tech used (small, muted)
- Link to GitHub or live site

Carries over all 6 existing projects from v2 (3 data, 3 code).

### About (`/about`)

Two short paragraphs + links. Based on v2 about-me content. No skills grid, no logo carousel — those felt like resume padding.

## Design System

### Typography

| Role | Font | Size / Weight |
|---|---|---|
| Nav, labels, metadata | system-ui | 14px, regular |
| Body prose | Inter | 16px / 1.7 line-height |
| Post body prose | Lora (serif) | 18px / 1.8 line-height |
| Section headings | Lora | 20px, normal weight |
| Post title | Lora | 36px, normal weight |
| Homepage name | Lora | 24px |

Both fonts loaded from Google Fonts.

### Color Palette

```css
--bg:       #F9F7F4   /* warm off-white */
--text:     #1A1A1A   /* near-black */
--muted:    #888888   /* dates, metadata, footer */
--accent:   #2A5C8A   /* links — restrained navy */
--border:   #E8E4DF   /* separators */
```

### Spacing

Max content width: `680px`. Generous vertical spacing between sections (`4rem` gaps). The whitespace is intentional — it signals confidence, not emptiness.

### Interactions

- Links: no underline default, underline on hover
- Writing list rows: title color transitions from `--muted` to `--text` on hover (subtle, not flashy)
- No page transitions, no scroll-triggered animations
- Mobile: single column, nav collapses to stacked or hamburger at `< 640px`

## MDX Post Frontmatter Schema

```typescript
// src/content/writing/_schema.ts
{
  title: string        // post title
  date: Date           // publish date (YYYY-MM-DD)
  description: string  // one-line summary shown in list
  draft?: boolean      // true = excluded from build (default false)
}
```

Example post file:

```mdx
---
title: "My First Post"
date: 2026-05-28
description: "A short description for the writing list."
---

Post body starts here. Just write markdown.
```

## SEO

Not the primary goal, but built in correctly from the start so it doesn't need a retrofit.

### Per-page meta tags (in `Base.astro`)
- `<title>`: post title + " — Alan Wu" / page name + " — Alan Wu"
- `<meta name="description">`: post `description` frontmatter field; hand-written for static pages
- Canonical URL: `<link rel="canonical">` on every page
- Open Graph: `og:title`, `og:description`, `og:url`, `og:type` (article for posts, website for others)
- `og:image`: a single static social card image in `/public/` — one image covers all pages for v3, no per-post generation

### Structured data
- `<script type="application/ld+json">` on post pages with `BlogPosting` schema (name, datePublished, author, description)
- Author schema on About page

### Technical
- Astro generates static HTML — fully crawlable, no JS required for content
- Semantic HTML throughout: `<article>`, `<nav>`, `<main>`, `<time datetime="">` on dates
- All images have `alt` text
- `robots.txt` included, no pages blocked
- `sitemap.xml` via `@astrojs/sitemap` integration (one-line config addition)

### What's deferred
- Per-post OG image generation (can add with `@vercel/og` later)
- RSS feed (trivial to add with `@astrojs/rss`)

## Navigation Transitions

Smooth page-to-page navigation using Astro's built-in **View Transitions API** (`@astrojs/transitions`).

### Implementation
Add `<ViewTransitions />` to `Base.astro` — that's it. Astro handles the rest.

```astro
---
import { ViewTransitions } from 'astro:transitions';
---
<head>
  <ViewTransitions />
</head>
```

### Behavior
- Default: cross-fade between pages (~200ms). Feels instant, not theatrical.
- Nav links: no full page reload — Astro intercepts clicks and swaps content client-side
- Back/forward browser buttons work correctly (history is preserved)
- Fallback: full page load on browsers that don't support the View Transitions API (graceful degradation)

### Scoped transitions (optional per-element)
- Writing list items can slide up on enter using `transition:animate="slide"`
- Post title fades in with `transition:animate="fade"`
- Keep it subtle — the point is smoothness, not showiness
